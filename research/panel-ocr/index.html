Read a number from an instrument display — then forecast it

Many water meters only have a screen. This lab turns camera pixels into a time series, step by step: box (ROI, 讀值框) → find the text line (text detection, 文字偵測) → read characters (recognition, 文字辨識) → check (validation, 驗證) → place in time → forecast. Everything runs on this phone; no image leaves it.

Demo meter: a synthetic water meter streamed like a camera, so the true value of every frame is known and OCR accuracy can be measured. First use downloads the OCR models (≈13 MB) and OpenCV once.

How OCR works 原理

Text detection 文字偵測 · PP-OCRv5 det

A small segmentation network outputs, for every pixel, the probability that it belongs to text. The map is thresholded (DB, differentiable binarization, 可微分二值化), each blob becomes a box, and the box is enlarged (“unclip” ×1.5) because the network marks only the core of each glyph. Pieces on one line are merged, so split 7-segment digits become one line. Inside your box the tallest line is read; a slightly misplaced box therefore no longer cuts digits off.

Text recognition 文字辨識 · PP-OCRv5 rec + CTC

The line image is resized to 48 px high and cut into narrow vertical slices. For every slice the network gives a probability for each character and for “blank”. CTC decoding (connectionist temporal classification) keeps the best character per slice, removes repeats and blanks: 2 2 – 5 . . 7 → 25.7. Inside the number, letters that look like digits (O, S, I…) are re-decoded with digits only, and the reading then takes the weakest character’s confidence. Text before the number is kept as a label (pH, DO) and text after it as the unit (%, °C).

confidence = mean character probability   (min if any character was replaced)
It is the model's own score, not a calibrated probability of being right.

Validation 驗證 · nothing is guessed

A reading becomes a data point only if it is exactly one number, confidence ≥ 90%, inside min/max, the unit matches, and the decimal point is certain. With a fixed number of decimals a missing dot is restored only if the image or the model shows a dot at exactly that position (AUTO_DECIMAL_RECOVERY); a bare leading dot (.79) means a digit was cut off. With 3 photos, at least 2 must agree. Glare or a wrong box can make all photos wrong together (correlated error, 相關錯誤): a vote removes random slips, not shared ones.

Hand-held tracking 面板追蹤 · optical flow + ORB + RANSAC

At Start the lab stores a reference picture of the panel. Corner points outside your boxes are followed frame by frame with Lucas–Kanade optical flow (光流); every few frames they are re-matched to the reference so errors do not pile up, and ORB features re-find the panel after a jump. RANSAC keeps only consistent points and fits a homography (單應矩陣) that moves the boxes with the panel and straightens the crop. If too few points agree, the reading is marked TRACKING_ERROR instead of read from the wrong place.

From readings to forecasts 時間序列

Every sampling time is one tick. A rejected or skipped reading leaves a gap — it is never filled with the previous value, because a filled value would pretend the camera saw something it did not. The forecasts (Persistence, Kalman, Holt, ESN) are the same phone models as in the ESP32 Water Lab and are scored live. Compare the OCR quality table with the forecast table: one wrong but accepted reading (a false accept) pulls every forecast that follows.
